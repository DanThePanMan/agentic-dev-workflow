# Help make a decision

1. State the decision in one sentence. Include doing nothing when it is a real option.
2. Ask for the success measures and limits that matter: time, cost, safety, maintenance, performance, and user impact.
3. Check the relevant repository code and, when current external facts matter, use primary sources.
4. Compare only realistic options. For each, explain benefits, costs, risks, how hard it is to undo, and how certain the evidence is.
5. Give a recommendation and say what new fact could change it.
6. Ask the user to choose when the decision changes product behavior, architecture, cost, or security.

Use plain English. Do not make a material decision for the user or start implementing it.
