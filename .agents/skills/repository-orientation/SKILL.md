# Understand the repository

1. Read project instructions first, including `AGENTS.md`, `README`, and contributor notes.
2. Check the current Git state. Do not alter existing user changes.
3. Identify the main languages, dependency files, applications or libraries, and the usual test, type-check, lint, and build commands.
4. Read only enough of the folder layout to explain where the important code, tests, and configuration live.
5. Report:
   - What the project does.
   - The main tools and commands.
   - Important folders and rules.
   - Things you could not confirm.

Keep the report short. Do not inspect every file, make architecture recommendations, or edit project files unless the user asks.
